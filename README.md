# ianseo-lite

ScorekeeperNG(ISK-NG)で得点を入力できる、**予選だけ・1セッションだけ**の記録会向けの簡易システムです。
本家 ianseo とは独立していて(本家の DB・`Common/` などには依存しません)、このフォルダだけで動きます。

**置き場所は `Modules/Custom/ianseo-lite/`** です。ianseo 本体の更新は `Modules/Custom/` を触らないので(`Update/FileList.php`)、
更新しても消えません。メニューの「モジュール」→「ianseo-lite（簡易記録会）」から管理画面を開けます。
カスタムモジュール管理(`Modules/Custom/ModuleManager`)の有効/無効の切り替えにも対応します(無効にすると管理画面と端末 API が 403 になります)。
`data/`(SQLite の DB)と `config.local.php` はモジュールの更新でも残る設定にしています(`module.json` の `keep`)。
単体で別の場所に置いて動かすこともできます。

- バックエンド: **PHP + SQLite**(MySQL・Apache の専用設定は不要)
- 入力クライアント: 既存の **ScorekeeperNG**(モード: **Lite**)
- 対象: **WA(World Archery)の予選形式**。**1距離または2距離**で、1距離は屋外 **36射**(6射 x 6エンド)・屋内 **30射**(3射 x 10エンド)。
  つまり Outdoor 36射 / Outdoor 36射×2(72射) / Indoor 30射 / Indoor 30射×2(60射) の4形式。1セッション
- 部門: **リカーブ男子・リカーブ女子**のみ(コンパウンドなどは対象外)
- 順位: 全距離の合計 → 第1優先順位の点の本数 → 第2優先順位の点の本数(記録会設定で変更可。初期値は アウトドア X → 10、インドア 10 → 9)。すべて同じなら同順位(*)で、シュートオフ等で決める
- 出力: **スコアカード PDF**(白紙/得点入り)、**結果 PDF**、結果・全矢の CSV

本家 ianseo の ISK-NG Lite モードの通信(`Api/ISK-NG/v1/*`)を、予選に必要な部分だけ SQLite 上に再実装しています。
個人戦/団体戦のマッチ・エリミネーション・ゲート・Pro/Live モードは対象外です。

## 入れ方(ianseo の Modules/Custom に置く場合)

```sh
cd <ianseo>/Modules/Custom
git clone https://github.com/e-donkun/ianseo-lite
```

更新するときは `git pull`(`data/` と `config.local.php` は Git 管理外なので残ります)。zip で入れる場合は
ianseo の「カスタムモジュール」→「新規追加」から、`ianseo-lite` フォルダの zip を指定します。

## 必要なもの

- PHP 7.4 以上(動作確認は 8.3)。拡張: `pdo_sqlite`, `mbstring`, `zlib`
- タブレットとサーバーが同じネットワーク(Wi-Fi)にあること

## 起動

ianseo と同じ Web サーバー(XAMPP など)に置いてある場合は、そのまま
`http://<サーバー>/<ianseoのパス>/Modules/Custom/ianseo-lite/admin/` を開きます(ianseo のメニューからもリンクしています)。

ianseo を使わず単体で試すだけなら、PHP の組み込みサーバーで足ります。

```sh
cd Modules/Custom/ianseo-lite
php -S 0.0.0.0:8080 -t .
# → http://<このPCのIP>:8080/        参加者向けの記録会一覧(右上の「管理」、各記録会の結果の右上の「設定」から管理画面へ)
# → http://<このPCのIP>:8080/admin/  管理画面(管理者メニュー)
```

管理画面は「管理者メニュー」から始まります。同梱の**サンプル記録会**(屋外 Outdoor 36射×2 と 屋内 Indoor 30射×2 の2つ。パスワードはどちらも `sample`)で動きを確認できます。
新しい記録会を作るには、まず画面下の「管理者パスワードを設定」で**管理者パスワード**を決め、管理者としてログインします(すべての記録会に共通。下の「セキュリティ」も参照)。

記録会のデータは記録会ごとに1つの SQLite ファイルで、`data/competitions/<記録会コード>.sqlite` に作られます。
`data/` は Web から見えないようにしてください(Apache は同梱の `data/.htaccess` で拒否。
nginx は `location ~ /ianseo-lite/data/ { deny all; }`)。
場所を変えたいときは、環境変数 `LITE_DATA_DIR` か、`config.local.php` を使います。

```php
<?php // config.local.php (任意)
return ['data_dir' => '/var/lib/ianseo-lite', 'timezone' => 'Asia/Tokyo', 'admin_password' => '固定したいパスワード'];
```

## 使い方

画面の作りは ianseo 本体のカスタムモジュール「スマホモード」に合わせています(上に記録会名とページ名、下にタブ: ホーム / 参加者 / 的番号 / 端末設定 / 点数管理 / 結果。上部バーには記録会名と [記録会コード] を出します。
一覧はカード、編集は下から出るシート)。

0. **管理者メニュー** — 記録会を開く・切り替える・新しく作るのは、この画面だけで行います(全体管理者はホームの左上の「<」で戻ります。全体管理者でログインしていないと一覧は出ず、記録会コードを入れて、その記録会の個別パスワードで開きます(記録会結果の右上の「設定」からも開けます)。個別管理ではホームの「<」で記録会一覧に戻ります。上部バーの記録会名からは切り替えません)。
   記録会ごとに DB とパスワードが別で、パスワードはその記録会の SQLite の中にあります。**記録会を開く・切り替えるたびに、その記録会のパスワードを入れます**
   (前に開いた記録会のパスワードは覚えません)。記録会のパスワードの代わりに管理者パスワードを入れても開けます。
   画面下の「管理者ログイン」で管理者としてログインすると、どの記録会もタップするだけで開け、一覧の上に「新しい記録会を作成」
   (記録会名・競技形式・その記録会のパスワード)が出ます。**新しい記録会は、管理者としてログインしているときだけ作れます**。記録会コードは自動で付きます。
1. **記録会設定** — 記録会名と競技形式(Outdoor 36射 / Outdoor 36射×2 / Indoor 30射 / Indoor 30射×2)を選ぶ。競技形式と並べて**的の種類**(屋外: 10リング・6リング、屋内: 40cm 三つ目(既定)・10リング。前半・後半とも同じ的)を選びます。**結果の公開/非公開**はホーム(管理者画面ホーム)のトグルで切り替えます(新しい記録会は非公開。状態はバッジで表示、公開用の URL はコピーボタン付き)。画面の下の「管理」(タップで開く)で、この記録会のパスワードの変更・点数の全消去・**この記録会の削除**(データベースファイルごと削除。元に戻せません)ができます。
   タップで開く**詳細設定**には、距離の名称(2距離の初期値は 前半・後半、1距離は空欄)と、同点のときの**第1優先順位・第2優先順位**(ianseo の Points as 1st / 2nd Tie-Breaker)があります。
   優先順位は点をカンマ区切りで入力し(例 `10,X`)、見出しは点を + でつないだもの(10+X)が自動で付きます。初期値は アウトドア 第1=X・第2=10、インドア 第1=10・第2=9。記録会コードは記録会の作成時に自動で付く8桁の16進数で、入力は不要。
2. **参加者登録** — スマホモードの参加者一覧と同じ作りです(検索・部門で絞り込み、カードをタップで編集・削除)。「＋追加」で
   - **新しく入力**: 姓・名(横に並んだ入力欄)・所属・部門(男子 / 女子)。所属はこのサーバーの記録会から候補が出ます。
   - **過去の記録会から**: 所属を選ぶ → その所属だった選手にチェック → まとめて追加(同じ姓名の選手がいれば飛ばします)。
   CSV(UTF-8 / Shift_JIS)でもまとめて登録できます。
3. **的番号設定** — 的番号と位置(A〜F)の設定は別の画面です。的は「1的」「2的」…と表記します。やり方は2つで、どちらでもできます。
   - **割り当て表**(スマホモードの的番号と同じ): 参加者をタップして、空き枠をタップすると移動。参加者のいる枠をタップすると入れ替え。下の「未割当」からも選べます。上の ＋/− で**的数**と**選手数**(1的あたりの人数。1〜6 = A〜F)を変えられます。参加者のいる的・位置より小さくはできません。
   - **一覧**: 参加者ごとに的番号(例 `1A`)を直接入力します。小文字は大文字に、頭の 0 は取ります(`001a` → `1A`)。位置を省くと空いている最初の位置に入ります。的数・選手数より大きい番号を入れると、的数・選手数を自動で広げます(選手数は 6 まで)。
   - **的番号自動設定**(一覧・割り当て表の両方): 「未割当の参加者に自動割当」(空いている枠に部門順・登録順)、「割当をすべて解除する」、「同じ部門でシャッフルする」(点数のない参加者を同じ部門どうしで入れ替え)。
   **点数が入っている選手は動かせません**(端末は「的+位置」で選手を見分けるため)。
   **スコアカード PDF** は選手登録・入力状況のページから出力します。各カードに「その的のQR」を印刷します。
4. **端末設定**(下部タブ) — 「接続設定のQR」を ScorekeeperNG で読み取る(モード **Lite**)。QR が使えない場合は、アプリの設定にサーバーURLと記録会コードを手入力します(どちらもこのページに表示されます)。
   「的のQR」は ＜ ＞ で的を切り替えて表示します。2距離のときは「前半 / 後半 / 指定無し」を選べ、前半・後半のQRは読み取るだけでその距離の入力画面になります
   (1距離のときは切り替えなし。見出しは「1的」だけ)。「的QR一覧 PDF」も選んだ距離のQRで出力します。
   的のQR(またはアプリ内の的番号選択)でその的の選手が表示され、入力した得点が随時サーバーに保存されます。
5. **点数管理** — 参加者ごとのカードで進行(最終入力からの時間・エンド数・距離ごとの合計)を確認。「編集」で**素点の編集**(ScorekeeperNG と同じく、矢の枠をタップして的面の色のボタンで入力。素点削除・エンド削除。「編集内容を保存」で保存し、更新履歴は右上のボタンから)。確定は「全員を確定」でまとめて行い、確定すると端末からの入力をブロックします(確定を解除しても、端末は QR から読み込み直します)。
6. **結果** — スマホモードの速報と同じ作り。部門別の順位(合計 → 第1優先 → 第2優先)と的順の切り替え、カードをタップでスコアカード(エンドごとの 計・第1優先と第2優先の本数・累計と、距離ごとの小計)を表示。結果 PDF / CSV を出力。
   参加者向けの公開ページは管理画面(`admin/`)ではなく**トップ**(例 `https://<サーバー>/ianseo-lite/`)です。公開している記録会の一覧(1つだけならその記録会)が出て、
   `?c=<記録会コード>`(例 `https://<サーバー>/ianseo-lite/?c=5A4D0001`。`results.php?c=…` でも同じ)でその記録会の「記録会結果」。ログイン不要です。自動更新は開くたびにオフから始まり、チェックを入れると「30秒」から数字が減り、0 で更新します。右上の歯車「設定」から、個別パスワード(または全体管理者)でその記録会の管理者画面ホームを開けます。
   ホームのトグルで**公開にした記録会だけ**見られます(非公開の記録会は、管理者がこの URL を開いても一般と同じく 403。非公開のあいだは、管理画面の「結果」タブで確認できます)。一般向けのページには結果PDFだけを出し、結果CSVと説明文は出しません。

### 端末(ScorekeeperNG)と記録会

端末は記録会コードで記録会を指します。**端末が古い記録会のコードで接続してきたら、その記録会の DB を読み書きします**(いま管理画面で開いている記録会とは関係ありません)。
端末の登録(端末コード・電池・的)も記録会ごとの DB に入ります。記録会コードのないリクエスト(電池・言語など)は、その端末が最後に通信した記録会として扱います。

### サーバーURL について

設定は不要です。QR に入る URL は「ブラウザで開いている URL」から作ります。`localhost` で開いているとタブレットから届かないので、
LAN 上のアドレス(例 `http://192.168.0.10:8080/admin/`)で管理画面を開いてください。
端末の接続先 API は `<サーバーURL>Api/ISK-NG/` です(サーバーURL直下への POST も同じ API として受け付けます)。

## 得点データの扱い

- 矢は距離ごとに 1 文字 1 本の `arrowstring` で保存します(本家と同じ: `A`=M, `B`〜`J`=1〜9, `L`=10, `K`=X。小文字は疑義)。
- 端末から届いたエンドは、**空でないエンドだけを丸ごと置き換え**ます。端末が再同期で空の状態を送っても、他のエンドは消えません。
- 端末は **自分に割り当てられた的** の選手にしか書き込めません。確定済みのスコアカードは更新を拒否します。
- 端末・管理画面からの更新は、エンド単位で `score_log` に残ります(訂正ページで確認できます)。
- バックアップは `data/competitions/` の中の、記録会のファイル(`<記録会コード>.sqlite`、と同じ場所の `-wal`/`-shm`)をコピーするだけです。
- 1記録会だけだった頃の `data/lite.sqlite` があれば、最初のアクセスで `data/competitions/` へ自動で移します(パスワードはそのまま。記録会コードが `LITE` なら新しい16進数に変わるので、端末は QR を読み直してください)。

## セキュリティ

- 管理画面のパスワードは**記録会ごと**で、その記録会の DB の中にあります(ハッシュ)。CSRF トークンも使います。
- **管理者パスワード**は記録会ごとのパスワードとは別の、すべての記録会に共通のパスワードです(`data/admin.json` にハッシュで保存)。
  管理者はどの記録会も開け、新しい記録会を作れます(新しい記録会を作れるのは管理者だけ)。
  最初の設定は管理者メニュー画面の「管理者パスワードを設定」から行います。だれかに先に決められないよう、サンプル以外の記録会があるときは、
  その記録会のパスワードも入れて確かめます。`config.local.php` の `admin_password` に書いておくこともできます(その場合も管理者パスワードとして使えます)。
- 選手登録の「過去の記録会から」と所属の候補は、このサーバーにあるすべての記録会の名簿(姓名・所属・部門だけ)から出します(パスワードを覚えないため)。
- 端末の登録には記録会コード(ランダムな8桁の16進数)が必要で、これが合言葉になります。PIN はありません。登録済みの端末だけが API を使えます。
- 記録会結果のページと結果PDFは、ホームのトグルで公開にした記録会だけ誰でも見られます。CSV を含め、それ以外は管理者のみです。インターネットに直接公開する場合は HTTPS のリバースプロキシ配下に置いてください。

## サーバーへの自動反映(GitHub の main に push → さくらで git pull)

`deploy.php` が GitHub の Webhook を受けて、サーバーのこのフォルダで `git pull --ff-only origin main` を実行します。
Webhook の署名(Secret)を確かめてから動くので、ほかの人がこの URL を叩いても何も起きません。Secret を設定していなければ 404 を返して何もしません。
`data/`(記録会の DB)と `config.local.php` は Git の管理外なので、pull しても消えません。

リポジトリは非公開なので、サーバーが GitHub から取得できるようにしておきます。
`https://github.com/...` で clone して認証情報を保存している場合は、そのままで構いません
(サーバーで `GIT_TERMINAL_PROMPT=0 git pull --ff-only origin main` が入力なしで通れば OK。下の 1・2 と `deploy_ssh_key` は不要)。
そうでなければ、**読み取り専用の鍵(Deploy key)**を置きます。以下は さくらのレンタルサーバ の例です
(`<ユーザー名>` はサーバーのアカウント名、`~/www/ianseo-lite` は置き場所。ianseo の `Modules/Custom/ianseo-lite` に置くならそのパス)。

1. **SSH でサーバーに入り、鍵を作る**
   ```sh
   ssh-keygen -t ed25519 -N "" -f ~/.ssh/ianseo-lite_deploy
   cat ~/.ssh/ianseo-lite_deploy.pub
   ```
2. **GitHub に鍵を登録**: リポジトリの Settings → Deploy keys → Add deploy key に、表示された公開鍵を貼る(「Allow write access」は付けない)。
3. **サーバーに clone**(すでに置いてあるフォルダは、`data/` と `config.local.php` を退避してから置き換える)
   ```sh
   GIT_SSH_COMMAND="ssh -i ~/.ssh/ianseo-lite_deploy -o IdentitiesOnly=yes" \
     git clone git@github.com:e-donkun/ianseo-lite.git ~/www/ianseo-lite
   ```
4. **Secret を決めて `config.local.php` に書く**(`openssl rand -hex 20` などでランダムな文字列を作る)
   ```php
   <?php
   return [
       'deploy_secret' => 'ここにランダムな文字列',
       'deploy_ssh_key' => '/home/<ユーザー名>/.ssh/ianseo-lite_deploy',   // 絶対パスで
       // 'deploy_branch' => 'main',   // 省略時 main
   ];
   ```
5. **GitHub に Webhook を登録**: Settings → Webhooks → Add webhook
   - Payload URL: `https://<ユーザー名>.sakura.ne.jp/ianseo-lite/deploy.php`(置き場所に合わせる)
   - Content type: `application/json`
   - Secret: 4. と同じ文字列
   - Which events: **Just the push event**
6. 登録すると GitHub が ping を送ります。Webhook の「Recent Deliveries」が 200(`pong`)なら設定は完了です。
   以後 main に push すると自動で pull され、結果は「Recent Deliveries」の応答と `data/deploy.log` に残ります。

うまくいかないとき:
- 403 `Bad signature` … GitHub と `config.local.php` の Secret が違う。
- 500 で `Permission denied (publickey)` … Deploy key の登録漏れか、`deploy_ssh_key` のパス違い(鍵のパーミッションは 600)。
- 500 で `Not possible to fast-forward` … サーバー側のファイルを直接編集している。`git status` で確かめ、`git checkout -- <ファイル>` で戻す。
- 500 `Cannot run git` … PHP から外部コマンドを実行できない環境。その場合は、さくらのコントロールパネルの「CRON設定」で
  `cd ~/www/ianseo-lite && GIT_SSH_COMMAND="ssh -i ~/.ssh/ianseo-lite_deploy -o IdentitiesOnly=yes" git pull --ff-only -q origin main`
  を数分おきに実行する方法に切り替えてください(Webhook は不要)。

## テスト

```sh
php tests/run.php        # (このフォルダで実行) ScorekeeperNG との通信・採点・順位・PDF・複数記録会・的番号の移動を確認
```

## 構成

```
Modules/Custom/ianseo-lite/
├─ module.json            カスタムモジュール管理用のパッケージ情報
├─ menu.php               ianseo のメニュー「モジュール」にリンクを追加
├─ index.php              入口(端末のPOSTはAPI、ブラウザには記録会結果)
├─ results.php            参加者向けの記録会結果(公開にした記録会だけ。ログイン不要。トップ / を開いてもこれが出る)
├─ deploy.php             GitHub の Webhook を受けて git pull(サーバーへの自動反映。Secret を設定したときだけ動く)
├─ Api/ISK-NG/index.php   ScorekeeperNG の接続先
├─ admin/                 管理画面(管理者メニュー/ホーム/記録会設定/選手登録/立順/入力状況/結果/端末設定/PDF/CSV)
├─ src/                   ロジック(Db, Settings, Entries, Scoring, Results, IskApi, Pdf ...)
├─ lib/tcpdf/             PDF 生成(TCPDF 同梱。LGPL)。日本語は小塚ゴシック(kozgopromedium。PDF に埋め込まない CID フォント)
```

## 端末がつながらない・入力画面に進まないとき

1. 管理画面の「端末設定」→ 登録された端末の一覧を見る。
   - 端末が出ない → サーバーまで届いていない(サーバーURL・記録会コード、Wi-Fi、http/https を確認)。
   - 端末は出るが「的」が `-` → 的の選択(`manual`)まで進んでいない。選んだ的に選手がいるか(選手ページで的番号を割り当てたか)を確認。
2. それでも原因がわからなければ「通信ログ」をオンにして端末で同じ操作をし、ログ画面で
   `handshake → comp → manual → reconfigure` のどこで止まっているか、返事の中身を確認する。終わったらオフにしてログを消す。

端末へ返す JSON の項目の**型**(文字列か数値か)は、本家 ianseo と同じにしてあります(的面の `code` や `previous` は文字列)。
アプリは `scoring.targetface` と `targetFaces[].code` を突き合わせて入力画面の的を決めるため、型が違うと入力画面を組み立てられません。

## 制限事項・注意

- ScorekeeperNG の通信仕様は本家 ianseo のソース(`Api/ISK-NG`)から再現したものです。**実機アプリでの確認は、本番前に必ずリハーサルで行ってください**
  (接続→的選択→入力→確定→PDF の一連)。アプリの版によって挙動が異なる可能性があります。
- 「QR 読み取りの強制」「署名の正規表現」「GPS 設定」など Pro/Live 向けの端末設定には対応していません。
- WA 形式の予選(1〜2距離)・リカーブ男女・1セッションだけです。3距離以上、他の部門、マッチ戦が必要なら本家 ianseo を使ってください。
- 競技形式の変更は、得点が1本も入っていないときだけできます(得点の全消去で戻せます)。2距離対応より前に作った DB は、新規に作り直すのが確実です。
